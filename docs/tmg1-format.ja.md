# TMG1 フォーマット仕様書

[English](tmg1-format.md) | **日本語**

> ステータス: ドラフト。フォーマットは試作・改良中で、現行バージョン
> （`version = 2`）のみを文書化・サポート対象とします。過去の未公開リビジョンとの
> 後方互換は維持しません。

## 概要

TMG1 は ESP32 での再生に最適化した、軽量な 1 ビットモノクロ（ビットプレーン）
動画フォーマットです。ランレングス符号とエントロピー符号を組み合わせて小さくし、
XOR ベースの差分フレーム（I/P 構造）に対応します。圧縮は PC 上で Rust 製 CLI
（[`tmg1-cli`](https://github.com/tmg1-labs/tmg1-cli)）が共通 C++ コーデック
ライブラリ（[`tmg1-codec`](https://github.com/tmg1-labs/tmg1-codec)）の上で行い、
再生は ESP32 上で
[`tmg1-esp32-demo`](https://github.com/tmg1-labs/tmg1-esp32-demo) が担当します。

**推奨解像度: 128×64 ピクセル。**

特記がない限り、マルチバイト整数はリトルエンディアンです。`ULEB128` は符号なし
LEB128 可変長整数を表します。

---

## ファイル構造

```
+---------------------------+
| FileHeader (16 バイト)    |
+---------------------------+
| FrameChunk[0 .. N-1]      |
+---------------------------+
| IndexChunk (任意)         |
+---------------------------+
```

### FileHeader（16 バイト）

| オフセット | フィールド   | サイズ | 説明                                                              |
| ---------- | ------------ | ------ | ----------------------------------------------------------------- |
| 0          | Magic        | 4      | `"TMG1"`（0x54 0x4D 0x47 0x31）                                   |
| 4          | Version      | 1      | `0x02`                                                            |
| 5          | Flags        | 1      | bit0: MSB ファースト, bit1: 予約（未使用）, bit2: Range コーダ有効 |
| 6          | Width        | 2      | uint16                                                            |
| 8          | Height       | 2      | uint16                                                            |
| 10         | TimebaseNum  | 2      | 例: `1`                                                          |
| 12         | TimebaseDen  | 2      | 例: `30`（30fps の場合）                                         |
| 14         | KeyInterval  | 2      | キーフレーム間隔（例: `60`）                                     |

## フレームチャンク

```
+------------------------+
| FrameHeader (可変長)   |
+------------------------+
| Payload (可変長)       |
+------------------------+
```

### FrameHeader

| フィールド       | 型      | 説明                                                                                                   |
| ---------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| FrameType        | u8      | `0` = I フレーム, `1` = P フレーム（XOR 差分）                                                          |
| PTSDelta         | ULEB128 | 前フレームからの時間差                                                                                  |
| PayloadSize      | ULEB128 | 圧縮ペイロードのバイト数                                                                                |
| FrameFlags       | u8      | bit0: 行ごとのスタートビット, bit1: 行ごとの Rice k, bit2: フレームごとの Rice k（bit1 と bit2 は排他） |
| PredictionMethod | u8      | `0`: なし, `1`: Left, `2`: Up                                                                           |

## ペイロード

ペイロードに使うエントロピーコーダは `FileHeader.Flags.bit2` で選択します。

### Rice コーダ・ペイロード（既定）

Range コーダが無効のとき、ペイロードはランレングス符号（RLE）の後に
ゴロム・ライス符号で圧縮されます。フレームはスキャンラインの並びで、各データ行は
Rice 符号化されたランレングスを含みます。

#### 行の構造

```
[LineType][(1 のとき) LineData]
```

- **LineType**: 1 ビット（`0` = 変化なし／空, `1` = データあり）
- **LineData**:
  - `FrameFlags.bit0 = 1` のとき、スタートビット（1 ビット）
  - `FrameFlags.bit1 = 1`（行ごとモード）のとき、RiceK（3 ビット）
  - Rice 符号化されたランレングスの並び（`width` まで 0/1 の塗りを交互に）

#### フレーム単位モード

`FrameFlags.bit2` が立っている場合、行の前に単一の Rice `k` が置かれ、
行ごとの RiceK は省略されます。

```
[FrameRiceK (3 ビット)][Line ...][Line ...] ...
```

### Range コーダ・ペイロード

`FileHeader.Flags.bit2` が立っている場合、ペイロードは RLE 符号化**されません**。
代わりに、予測フィルタ適用後のビットプレーンデータを行単位で Range コーダで
圧縮します。各行は 1 ビットの行タイプ（`1` = データあり, `0` = 空行でスキップ）で
始まり、データ行ではその後に `width` 個のピクセルビットが順に続きます。空行の
スキップは Rice 経路と共通です。

Range コーダは算術符号の一種で、ビットの確率が 50% から離れているデータに対して
ゴロム・ライス符号より高い圧縮率を、より高い計算コストと引き換えに実現します。

#### 技術的詳細

- **コンテキスト付き適応周波数モデル** — 適応型 `FrequencyModel` が次ビットの確率を
  推定します。1 次コンテキストモデルにより、直前ビットの値で分布を切り替えます
  （直前が `0` 用と `1` 用の 2 分布）。各分布は一様（50/50）で初期化され、ビットごとに
  該当コンテキストのみ更新します。カウントは上限を抑え統計変化に追従するため、
  しきい値到達時に周期的にリスケール（半減）します。
- **符号化状態** — コーダは数値範囲を 2 つの 64 ビット整数で保持します。`low`
  （範囲の下端）と `range`（範囲の幅）です。ビットの符号化はモデル確率で範囲を
  狭め、`low` が徐々にビットストリームを形成します。
- **正規化** — `range` が小さくなると、`low` の最上位バイトを出力し、`range` を
  左シフトして大きさを回復します。デコーダは逆操作を行い、バイトを取り込んで
  同期を保ちます。

### I フレーム

- **Rice コーダ**: データを含む行のみを符号化（LineType = 1）。空（全ゼロ）行は
  I フレームでも LineType = 0 とマークされます。
- **Range コーダ**: ビットプレーン全体をコーダに渡します（行ごとの空行スキップは
  同様）。

### P フレーム

- **Rice コーダ**: 変化した行のみ LineType = 1。変化なしの行は前フレームの
  データを再利用します。
- **Range コーダ**: ビットプレーン全体の XOR 差分をコーダに渡します。同一フレームは
  VFR でスキップされますが、部分更新は非対応です。Range コーダ有効時、P フレームは
  常に完全な差分を含みます。

## IndexChunk（任意）

シーク対応のためファイル末尾に付加します。

| フィールド | 型      | 説明                       |
| ---------- | ------- | -------------------------- |
| Magic      | 4 B     | `"TMGX"`                   |
| Count      | ULEB128 | フレーム数                 |
| Offset[i]  | uint64  | フレーム `i` のファイル位置 |

## 予測フィルタリング

RLE + Rice（または Range）符号化の前に、TMG1 はフレームデータ（P フレームでは
差分データ）に予測フィルタを適用できます。エンコーダはフレームごとに圧縮ペイロードが
最小になる方式を選び、`FrameHeader.PredictionMethod` に記録します。

| ID  | 方式   | 順方向フィルタ                              | 逆方向                                  |
| --- | ------ | ------------------------------------------- | --------------------------------------- |
| `0` | なし   | —                                           | —                                       |
| `1` | Left   | `filtered[x] = raw[x] ^ raw[x-1]`（バイト） | `raw[x] = filtered[x] ^ raw[x-1]`      |
| `2` | Up     | `filtered[y] = raw[y] ^ raw[y-1]`（バイト） | `raw[y] = filtered[y] ^ raw[y-1]`      |

エンコーダは 3 方式すべてを試し、ペイロードサイズを比較して勝った ID を書き込みます。
デコーダは ID を読み、展開後に対応する逆フィルタを適用します。

## ESP32 デコード手順の概要

1. FileHeader を読む。
2. 各フレームについて:
   - FrameHeader を読む。
   - 各行について: P フレームかつ LineType = 0 なら前の行をコピー、
     そうでなければ復号してピクセルを再構築する。
   - P フレームなら前フレームと XOR する。
   - 逆予測フィルタを適用する。
   - フレームを表示する。
